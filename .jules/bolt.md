## 2025-05-26 - Optimized duplicate checking from O(n^2) to O(1) in local data store fallback
**Learning:** The application uses a local JSON file (`data/store.json`) as a database fallback. In the previous implementation of `addJobs`, checking for duplicate jobs against all existing jobs was done using an O(n) array `.some()` call for every job in a batch, resulting in an O(n^2) operation. Because the entire store is loaded in memory as a large array, this becomes a major performance bottleneck as the data grows, particularly because it runs synchronously on the main thread.
**Action:** When working with the local fallback store (`store.ts`) for uniqueness/duplicate checks or bulk relational data operations, use `Set` or `Map` structures to establish O(1) lookups upfront. Ensure that when checking batches, items found to be unique are dynamically added to the Set/Map to prevent duplicates within the batch itself.
