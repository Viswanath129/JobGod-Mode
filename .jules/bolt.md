## 2024-03-24 - Avoid O(N²) when filtering local JSON database fallbacks
**Learning:** This codebase uses `store.json` via a local array loading system (`loadLocalStore`) as a fallback database when Supabase is disabled. Batch operations (like `addJobs` discovering thousands of new job leads against thousands of existing job entries) were using `Array.prototype.some` coupled with multi-field equality checks inside loops, creating massive O(n*m) blocking bottlenecks on the main thread.
**Action:** When working with large batch operations against the local store fallback (like adding/filtering jobs or applications), ALWAYS preload existing identifiers into `Set` or `Map` data structures first for O(1) lookups, and dynamically update the `Set`/`Map` within the loop to catch duplicates inside the batch itself.
