## 2024-06-04 - O(n^2) Bottleneck in Array-based local storage
**Learning:** The `store.ts` file acts as a local fallback database, but the unique job checking (`addJobs`) previously relied on scanning all existing jobs (Array.prototype.some) for every new job using a relatively complex equality check stringing together 4 fields or URL checks, making batch insertion effectively O(N*M) where N is the current job size and M is the batch size. As the store grows, this severely degrades performance of the daily job discovery agent.
**Action:** When working with local file-based arrays like in `store.ts`, utilize `Set` objects dynamically populated at the start of batch operations for lookups. If objects need to be evaluated based on uniqueness across multiple fields, compute "fingerprints" (hashing proxy) first, store them in a Set, and compare against the Set for O(1) performance.
